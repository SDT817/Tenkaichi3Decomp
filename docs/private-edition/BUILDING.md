# Building and checking private edition 0.17

This publication preserves the working source and historical build adapters.
It does not claim that every historical script is portable or that Linux/macOS
were revalidated. The accepted shipped build is Windows x64.

## Verify the published endpoint

Run from the repository root with Python 3:

```powershell
python -X utf8 development/verify_recorded_source.py
```

The verifier checks all 1,235 files in the retained r22 source manifest. Only
publication changes to the root README and ignore rules are allowed; all other
original files must match their recorded SHA-256. New collaboration files do
not affect that check. After making source changes, a mismatch is expected:
commit the change with its tests rather than changing the historical manifest.

## Full Windows game build

See `docs/port/README.md`, `port/release/README.md`, `port/tools/toolchain.py`
and `local/build_windows.py` for the upstream build and the retained Windows
adapter. The existing adapter expects a tool root containing:

- `mingw64/bin/`: the MinGW Windows GCC/G++ toolchain and its runtime.
- `ucrt64/`: the LLVM/libclang, SDL3 and shader tool dependencies used locally.
- Python's `clang.cindex` module compatible with that libclang.

Set the location explicitly on another machine:

```powershell
$env:BT3_LOCAL_TOOLS = 'D:\BT3-Wii-tools'
$env:PYTHONUTF8 = '1'
python -X utf8 local/build_cn8.py
```

Despite its historical name, `build_cn8.py` runs the full compiler/linker over
the source in the current checkout, including the current lobby and Test4
files. It does not restore old CN8 source. Outputs are in `port/build/`,
including matching `bt3.exe`, `.mem` and data generated by the original build.
Inspect the actual compile/link logs and reject incomplete object sets.
Development output must stay separate from an installed signed release.

Do not use `local/build_lobby22.py` or other historical incremental adapters
as a clean-checkout build: those explicitly compare/reuse sibling r20/r21
objects. They are preserved for provenance, not made portable in this
publication. The upstream Docker/release scripts are also retained, but this
publication does not certify a new container or platform build.

## Windows launcher

With a Go toolchain on PATH, build in `port/lobby/private_gateway`:

```powershell
go test ./...
go build -trimpath -ldflags='-s -w -H=windowsgui -X main.integrityVersion=0.17' -o BT3Launcher.exe .
go build -trimpath -ldflags='-s -w -X main.integrityVersion=0.17' -o BT3Connect.exe .
```

The GUI build is distributed under the name `启动游戏.exe`. It expects external
server configuration and a public trust certificate; these are deployment
inputs, not embedded administrator credentials.

For development, launch the locally built game directly instead of the
release launcher: the latter intentionally repairs changed signed files back
to official private-edition 0.17. Do not point experimental signing keys at
the existing production update endpoint. A separate server/key must have its
corresponding public identity compiled into development builds.

## Tests

The server's pure-Python checks can be run without game resources:

```powershell
Push-Location port/lobby
python -X utf8 -m unittest test_lobby2 test_directory test_room_settings test_eight_seats test_presence test_room_versions test_pause_room
Pop-Location
```

`local/tests/` additionally preserves compiled real-handler controls,
expression, editor, settings and Test4 checks. Read each runner first: some
reference the original tool path, installed resource packs, baseline sibling
snapshots, or a local Caddy/TURN installation. Full multiplayer, skill effects,
visual text and frame pacing still require the matching resources and live
gameplay tests. Previously recorded tests are historical evidence, not claims
of fresh tests on every collaborator's machine.

## Localization maintenance and resources

The game runtime consumes external audited Chinese font/catalog/archive
resources. Source for their construction and review is preserved under
`development/analysis-tools/`; all local same-directory Python imports of the
selected builders are included. These historical scripts depend on Pillow,
font tools, prior analysis tables and/or locally extracted game data; some
have deployment side effects. Inspect paths before execution. They are not
automatically run by the game compiler.

ISO/disc archives, patched game archives, raw texture/glyph extractions and
compiled releases are not in this source repository. Keep them in a separate
local workspace, retain applicable font/game licenses, and acquire the matching
audited pack from its maintainer when reproducing translated visuals.
