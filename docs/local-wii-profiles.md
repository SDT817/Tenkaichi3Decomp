# Wii 本地预设与分享码（r11）

进入 F1 → 控制 → Wii，可在“控制分离”旁输入预设名，然后保存；下拉选择预设后自动读取并应用。相同名称的保存覆盖同名预设，删除有确认。配置文件保存到游戏目录的 `wii_profiles/*.ini`；设置了 `BT3_SETTINGS` 时，保存在该设置文件旁的 `wii_profiles`。

“导入 / 分享”有四项：

- 从 Dolphin 导入：同时扫描 `%APPDATA%/Dolphin Emulator/Config/Profiles/GCPad/*.ini` 和系统文档目录下的 `Dolphin Emulator/Config/Profiles/GCPad/*.ini`。文档目录使用 `SDL_GetUserFolder(SDL_FOLDER_DOCUMENTS)` 获取，支持重定向/OneDrive；列表标记 AppData / 文档，同一路径不重复列出。一份直接导入，多份列出名称供选择；没有找到时提示手动导入。转换后的文件以 `Dolphin - 原名` 保存为本地预设。
- 分享码导入：粘贴其他改版玩家的 `BT3W1:`、`BT3W2:` 或 `BT3W3:` 分享码。成功后立即应用并持久保存当前 Wii 配置，可另起名称保存为列表中的预设。
- 手动导入：SDL 原生文件选择器，支持 Dolphin GCPad `[Profile]` INI 和本地保存的 `[BT3 Wii Profile]` INI。文件和分享码全部验证成功才会修改当前设置。
- 分享：编码当前正使用的 Wii 配置，点击复制分享码。分享始终使用当前已生效的配置。不包含存档、游戏数据、玩家名、IP 或手柄设备标识。

预设读取、Dolphin 导入、手动导入和分享码导入都仅作用于当前玩家的当前分离状态，绝不自动切换“控制分离”。分享记录来源的控制分离状态、当前配置的 26 个有效动作表达式/范围、死区与震动设置。PS2 键位、另一玩家和另一套 Wii 表达式保留；死区/震动仍采用官方与 r3 的每玩家设置。手柄使用接收方为该玩家选择的当前手柄，不照搬发送方槽号。旧 `bt3_wii_controls.ini` v2 不变，r3 / r4 可以直接覆盖更新；可移植预设是额外的独立文件，不是两玩家/两套模式的完整设置备份。

## Dolphin 来源与转换

参考 Dolphin 10912，源码修订 `82fd7f576e1dff6b616ff088955c18aa76ed45d5`：

- `DolphinQt/Config/Mapping/MappingWindow.cpp`：可编辑列表、按名称保存、读取 `[Profile]` 和目录 `Profiles/GCPad`。
- `Common/IniFile.cpp/.h`：UTF-8 BOM、CRLF、按首个等号拆分、去两端空白和双引号、大小写无关节/键查找。只读子集保存在 `port/third_party/dolphin/Common/ProfileIni.h`，保留原版权许可。
- `InputCommon/ControllerEmu/ControlGroup/ControlGroup.cpp`：`group/control` 和 `/Range` 读取；范围以百分比保存，未指定为 100。
- `InputCommon/ControlReference/ExpressionParser.cpp`：继续直接使用原词法和表达式算法。
- `ControllerInterface/DInput/NamedKeys.h`、`DInputKeyboardMouse.cpp` 和 `XInput/XInput.cpp`：设备/按键名称及轴方向。鼠标原有采样算法仍沿用 r3。

| Dolphin GC 配置项 | Wii 动作 |
| --- | --- |
| Buttons/A / B / X / Y / Z | 攻击 / 飞行 / 防御 / 气弹 / 聚气 |
| Buttons/Start | 开始 / 暂停 |
| Main Stick/Up/Down/Left/Right | 移动上/下/左/右 |
| C-Stick/Up/Down/Left/Right | 换人 / 变身 / 左视角 / 右视角 |
| Triggers/L / R | 高速下降 / 高速上升 |
| Triggers/L-Analog / R-Analog | 下降 / 上升 |
| D-Pad/Up/Down/Left/Right | 方向键上/下/左/右 |

Dolphin GC 没有独立的选角色和暴血动作，因此文件按组合布局解析，再按当前分离开关应用。组合 → 分离：左视角复制给“上一个角色”，右视角复制给“下一个角色”，暴血使用 `(左视角) | (右视角)`；复制相应输入范围并保留括号。分离 → 组合：忽略独立的上一个/下一个角色、暴血，保留左右视角。另一套 Wii 表达式不改动，暴血的战斗双击算法不变。Dolphin 键鼠和 XInput 可以在同一逻辑表达式混用，XInput Y 轴符号转换到 SDL。支持现有常见 Windows 键鼠名称和数字键盘；GRAVE 等特殊键通过安全名称和 SDL 扫描码对应。无法对应的键名会留空受影响的动作并提示，其它动作照常导入。通用 DirectInput/SDL 原始手柄编号因后端及设备的轴/按钮排列不固定，不猜测转换；遇到此类输入只留空对应动作并提示重新绑定，其它动作继续导入。Dolphin 的门限校准/八角门、Modifier、震动输出表达式等不是移植版的输入动作，不导入；数值死区保留移植版现有算法，输入范围取整到已有整数百分比。

对于不同的非空左右表达式，如果输入范围不一致，单条 Dolphin OR 表达式无法无损表达两个独立范围，导入会明确提示先统一范围；超出原有表达式长度/运算符/深度上限也会拒绝，当前配置保持不变。同一表达式取较大的范围，只有一边非空时直接复制该边。没有改动原解析器和输入求值算法。

## 分享码格式

这是独立改版新增功能，Dolphin 没有此格式。`BT3W2:` 先将 UTF-8 `[BT3 Wii Profile]` INI 用 zlib 压缩，再做无填充 Base64URL；负载是压缩数据和其 `SDL_crc32(0, data, size)` 值的 4 字节小端形式。保留旧的未压缩 `BT3W1:` 读取能力。INI 内 `Format=1`，动作编号沿用 r3 的 0–26，跳过无作用的 12，避免旧表达式错位。版本未知、截断、非法字符、非规范尾位、校验不符、过大文档和无效表达式均拒绝。允许复制时在码中加入空白/换行；校验用于发现复制损坏，不是身份签名。

文件上限 1 MiB，单条表达式继续使用 r3 的 16,383 字节、1,024 个运算符、64 层括号限制。分享码及文件只解析为按键表达式，不包含脚本执行、网络请求或协议行为。

2026-10-29 起新生成 `BT3W3:`，旧 W1/W2 仍可导入。W3 不再压缩完整 INI，而是以固定编号顺序保存 26 条 UTF-8 表达式（0–11、13–26），每条前面记录字节长度，空绑定保留。二进制 schema 1 依次记录：版本字节、来源分离状态字节、两个死区和震动开关/强度、非默认输入范围条目、26 条表达式。整数使用无符号 LEB128，有符号参数先作 ZigZag；非默认范围保存原动作 ID 和数值。外层继续使用相同的 zlib、CRC32 和 Base64URL。编号和 schema 固定，不能按界面顺序重新排列。

分享前复用 Dolphin 10912 的 lexer，仅对纯 ASCII 英文字母输入名去掉反引号，去除 token 之间的排版空白，保留括号、运算顺序、设备前缀和键名内部空格。数字、F1、鼠标/摇杆、带空格和标点的名称继续引用；解析器接受的整条裸键名也转换成安全引用。导入 W3 后给 `&`、`|`、`+`、`!` 补可读空格，例如 `J | F`、`N & ! SPACE`，不重新添加纯字母名称的反引号。达到原长度上限的合法表达式若补空格会超限，保留紧凑文本；不为显示空格拒绝有效配置。文件保存格式与其它导入路径保持原样。所有参数及接收端分离规则保留；未知版本、非法/重复范围 ID、整数溢出、截断和多余负载均拒绝，失败不覆盖现用配置。

## 继续合并官方更新

先取 `records/code-history/from-official-0.1.38.9.patch` 和对应官方源码，以新版官方为起点三方合并。优先核对 `ui.cpp` 的缩放、Wii 布局及预设栏三个调用点；预设主体独立在 `control_profiles*`/`control_profile_ui.cpp`，以后官方修改 UI 时冲突范围较小。重新运行保存的检查，尤其要验证 `.mem` 的状态范围非空，以及受保护联机源文件和编译对象与新版官方一致。

## r5 菜单操作与汉化

Wii 游戏菜单、暂停菜单与结算菜单使用绑定的移动左摇杆，十字键不再控制菜单移动。采用原 `Pad_Update` 的 0.5 阈值、主轴选择与 `Pad_CalcRepeat` 连发；PS2 和战斗输入不变。F1 控制页仍只允许键鼠操纵界面。联机窗口和新增设置的中文只改显示字符串；服务错误在 UI 层查表翻译，网络源文件、设置键与协议保持官方不变。
